# Platform and cloud TTS evidence for weak phones

Research date: 2026-10-13. Scope: native platform engines, traditional compact engines, and cloud alternatives. This is a source review, not an executed mobile benchmark. No service synthesis, downloads, installs, or production changes were performed.

## Decision implications

Keep Edge primary as requested. For a fallback that must work without connectivity on weak phones, benchmark the installed **system voice first** on Apple and Android, then compact independent engines. This ordering is an engineering hypothesis based on deployment footprint and integration, not a measured latency ranking. A second cloud provider covers provider failure but cannot cover loss of connectivity. Cloud inference avoids local model compute, but network, decoding, buffering, retries, and server queueing still contribute to the user's wait.

Apple/Android APIs are provider interfaces, not portable model names. Voice, OS, downloads, and Android engine vendor must be recorded in every result. No primary source reviewed establishes that any engine is fastest on every phone. Nor do Apple API documentation or Android voice metadata supply comparable pt-BR TTFA/RTF measurements.

## Minimum fair benchmark

Measure request-to-first **audible** audio (TTFA), first returned audio byte/buffer (TTFB), total synthesis wall time, audio duration, RTF = wall synthesis/audio duration (smaller is faster), peak RSS, CPU/energy, underruns, failure rate, and p50/p95. Keep cold-start/model load/download separate from warm inference, while also reporting the user's full cold-start wait. Use identical pt-BR source text, output normalization, chunk sizes, and playback policy; equal speaking rate matters because changing audio duration alters RTF.

For offline candidates test the oldest supported physical phone and a representative low-end Android, with airplane mode, low memory, sustained chapters, and cancellation. Simulator results characterize the host, not an A9 phone. For cloud run Wi-Fi, realistic weak mobile connectivity, connection cold/warm, dropped connection, timeout/failover, identical concurrency, and endpoint region. Vendor 75/90/200 ms numbers must remain in a separate published-claims column; never merge them with local client observations or use them to declare a global winner.
