# Lightweight TTS shortlist for the native Apple app

Research date: 2026-10-14. This note records the primary-source review phase; subsequent authorized physical-phone measurements are reported in [the benchmark results](2026-10-14-tts-phone-benchmark.md). The five entries below are benchmark candidates, not a measured quality ranking. Two Piper checkpoints are deliberately separate entries: both explicitly support Brazilian Portuguese, unlike the smallest Kitten release. The user subsequently authorized downloads, an Edge baseline, isolated benchmarking, and deletion of downloaded test assets. Edge remains primary and Piper remains suspended in production.

## Native route and evidence boundaries

Sherpa's current published latest release is v1.13.8. Its tagged C ABI already contains VITS, Kokoro, Kitten, Pocket and Supertonic configuration structures plus incremental generated-audio callbacks. Therefore the cached version number alone does not justify an upgrade. Match headers, linked library, Rust bindings and model formats; API presence does not prove the local build enabled each family. Use a benchmark-only native harness through the C ABI/Rust boundary, preserving product routing. [Release](https://github.com/k2-fsa/sherpa-onnx/releases), [tagged header](https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/v1.13.8/sherpa-onnx/c-api/c-api.h).

For Pocket PT, either export the exact Portuguese checkpoint into compatible graphs or validate an existing native Rust implementation against those weights/tokenizer. Do not benchmark the English sherpa package and relabel it Portuguese. Supertonic ships upstream Swift, iOS and Rust examples, providing another native route if the existing binding lacks its configuration. [Pocket examples](https://k2-fsa.github.io/sherpa/onnx/tts/pocket.html), [Supertonic examples](https://raw.githubusercontent.com/supertone-oss-archive/supertonic/main/README.md).

Pocket upstream reports about 200 ms to its first chunk and approximately six times realtime on a MacBook Air M4 CPU using two cores. These are author claims, not results from this app, iPhone 16e, a weak phone, cold loading, or Portuguese. No comparable controlled five-checkpoint native phone benchmark was established by this review. [Author claims](https://github.com/kyutai-labs/pocket-tts).

Benchmark identical pt-BR short/medium/long fixtures with accents, dialogue, names, dates, numbers and abbreviations. Save cold load plus TTFA, warm TTFA p50/p95, total generation/audio-duration RTF, peak RSS, complete required asset bytes, output sample rate, threads, hashes, runtime version and failures. Separate first PCM callback from first playable file and first audible playback. Preserve native sample rates for inference timing; report resampling/export separately. Qualitative listening must examine missing/repeated words and Brazilian pronunciation. Host results establish feasibility only; physical iPhone results are needed for phone conclusions.

## Why the tiny English alternatives do not displace these five

Kitten Nano 0.8 int8 remains an optional English control: official ONNX is 24.4 MB and voices add 3.28 MB, rather than a 25 MB complete install. Its Apache-2.0 card lists eight voices; the lightweight checkpoint does not establish Portuguese support. Do not attribute the newer 1.7B multilingual KittenTTS 2 capabilities to this tiny model. [Exact nano files](https://huggingface.co/KittenML/kitten-tts-nano-0.8-int8/tree/main), [nano card](https://huggingface.co/KittenML/kitten-tts-nano-0.8-int8), [family distinction](https://github.com/KittenML/KittenTTS).

The broader exclusions and weak-ARM published baselines are retained in [the previous inventory](2026-10-13-compact-tts-models.md). This shortlist does not claim every contemporary checkpoint was tested or that parameter count predicts latency.

## Follow-up: existing Portuguese ONNX exports

The user subsequently authorized benchmark downloads and six comparisons including Edge. This follow-up only reads metadata/source; it downloads no weights and executes no model.

A ready six-layer Portuguese ONNX bundle exists in `KevinAHM/pocket-tts-onnx/onnx/portuguese`. Repository metadata lists `flow_lm_main_int8.onnx` (76,341,079 bytes), `flow_lm_flow_int8.onnx` (9,962,530), `mimi_decoder_int8.onnx` (22,684,077), `mimi_encoder.onnx` (39,768,446), `text_conditioner.onnx` (16,388,344), `tokenizer.model`, `bundle.json` and `bos_before_voice.npy`. The bundle uses schema 2 and `insert_bos_before_voice=true`; it exposes pretrained voice names but the card says voice states are fetched from Kyutai. Export code is Apache-2.0; model card declares CC BY 4.0. Exact source-weight revision still requires provenance validation. [Converter's card](https://huggingface.co/KevinAHM/pocket-tts-onnx), [artifact metadata](https://huggingface.co/api/models/KevinAHM/pocket-tts-onnx/tree/main/onnx/portuguese).

This is not a ready sherpa Portuguese package. Open upstream issue #3755 reports that renamed newer graphs plus converted vocabulary still produce truncated or invalid audio: newer checkpoints require BOS voice conditioning absent from the January protocol; some exports also use unsupported FP16 state tensors. Treat the issue's symptom observations as reporter evidence, rather than a local reproduction. [Upstream issue](https://github.com/k2-fsa/sherpa-onnx/issues/3755), [tagged model implementation](https://raw.githubusercontent.com/k2-fsa/sherpa-onnx/v1.13.8/sherpa-onnx/csrc/offline-tts-pocket-model.cc).

A native executable route exists through the MIT C++17 fork `netai369/PocketTTS.cpp-multilingual`, which explicitly supports Portuguese and automatically prepends `bos_before_voice.npy`. It uses ONNX Runtime, SentencePiece and dr_wav and retains CLI/shared-library inference. Its CMake supports macOS/Linux/Windows; it does not provide an iOS build target. A phone harness therefore needs a separate build against iOS ORT and SentencePiece plus the C FFI, not merely a new sherpa configuration. The macOS CLI is the smaller feasibility experiment. No build or synthesis was attempted in this research. [Native fork](https://github.com/netai369/PocketTTS.cpp-multilingual), [build definition](https://raw.githubusercontent.com/netai369/PocketTTS.cpp-multilingual/master/CMakeLists.txt).

Another packaged option, `Alias-Alias/pocket-3-3-0-tts-onnx`, supplies official preset states and source-lock/checksums without a cloning encoder. Its schema 3 requires a compatible consumer and explicitly differs from April exports; no ready Swift adapter was established here. It avoids generating a new clone, but does not eliminate the native adapter requirement. [Export author's card](https://huggingface.co/Alias-Alias/pocket-3-3-0-tts-onnx).
