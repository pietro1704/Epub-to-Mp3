## Compatible adoption candidates

1. **Chapter-boundary sleep mode.** Add a small mode to the existing player rather than another timer subsystem. Acceptance: stop before playback of the next chapter; segment rollover within the same chapter must continue; speed changes must not move the boundary. XCTest must cover ordinary playback, streaming segment transitions, cancellation, manual seeks and switching books. Native iOS/macOS execution is required before claiming delivery. Inspiration: Audiobookshelf's linked timer source and Readest's linked TTS hook.
2. **Context-backed reader resume fallback.** Investigate a versioned stored location containing chapter/resource identity and a short textual anchor, with the current character/fraction fields as fallback. Acceptance: font/orientation changes preserve the passage; repeated text is resolved within the correct resource; missing/changed resources degrade safely; old saved entries decode. Test at `ReaderProgressStore` and the native restoration seam. Inspiration: Readium's linked Locator and Navigator guide. This must never replace the exact raw offset required during chrome transitions.
3. **Audit sentence-follow fallback rather than rebuild it.** First measure existing timing availability for generated segments. If a gap is demonstrated, expose reliable current sentence and gracefully fall back to chapter progress when timing is absent. Acceptance: no stale highlight after chapter/book switch or cancellation; no inferred word accuracy without timestamps. Rust contract tests own emitted timing identity; native XCTest owns following/highlighting. Inspiration: Readest's linked TTS hook. Status: investigation candidate, not a confirmed missing feature.
4. **Audit mixed-result import recovery.** Exercise the existing batch result path with one valid file, one malformed file and a duplicate; propose a compact retry action only if the current UI loses failures. Acceptance: successful files remain imported once, failed files remain retryable, source files remain intact, cancellation does not mark unfinished files processed. Existing importer and library tests are the starting point. This is an independently derived local usability check; upstream evidence here does not establish comparative superiority.

## Decision boundary

The user selected reading and audio synchronization as the priority after this comparison. Prioritize a measured sentence-follow audit and context-backed resume; keep chapter-end sleep and import work secondary. Sentence-follow work remains evidence-gathering until a user-visible gap is reproduced. Retain Swift UIKit/AppKit, Rust conversion ownership, explicit model installation and opt-in online fallback. Do not adopt upstream cloud sync, Tauri, remote audiobook servers, automatic voice downloads or a replacement reader solely because these projects provide them. No third-party code, model, dependency or service was adopted by this reader comparison; the index tracks the separate bounded catalog adaptation.
